# 账号名称、趋势起点与 OpenAI 用量重置设计

方案已按用户确认方向实现，并完成本地构建、测试和实际组件视觉检查。分支：`feat/account-usage-reset-ui`，基于 `main` 的 `99b7e3d`（v0.64.11）。

当前约束：保留现有表格行高；消除重复信息；统一签到与重置标签外观；主表仅展示主额度中周期最短一档的百分比，不显示周期；沿用悬浮详情并移除其顶部重复账号名；重置按钮不显示数量；确认时显示目标账号与当前可用数量。

## 1. 账号名称统一显示

“名称”指账号管理中用户填写的 `name`，不使用邮箱、渠道名或套餐名替代。通过渠道的 `managed_remote_account_id` 映射账号列表；复用现有 `resolveManagedChannelAccountName` 及请求明细的账号映射方式。

| 位置 | 设计 |
| --- | --- |
| 本月请求趋势图例 | `Gmail · OpenAI 20X`，账号名优先、渠道名弱化；图例项按空间换行，终端在分布和可用渠道分组中显示 |
| 趋势悬浮详情 | 紧凑三列显示名称、渠道及当日成功请求数量；日期只在顶部出现一次 |
| 渠道使用分布 | 同一行显示终端、`账号名 · 渠道名` 与占比／用量，保留现有进度条与行间距 |
| 可用渠道顺序 | 保留序号、箭头与重试次数；节点单行显示 `账号名 · 渠道名`，不增加节点高度 |
| 渠道统计 | 在“渠道”前新增“名称”列，可排序；渠道与终端保持独立列 |

统计分组继续使用 channel ID，不能按显示名合并，同账号多个渠道仍分别统计。未绑定账号的渠道显示 `—`；绑定信息缺失也不猜测账号名。长名称保留可访问的完整内容，不让标签挤掉数量。账号重命名、渠道重新关联后刷新映射。

现状证据：`ui/src/pages/channels/index.tsx`、`ui/src/pages/logs/index.tsx` 已实现账号映射；概览、分布、可用渠道和渠道统计仅展示渠道名。

## 2. 月初折线起点

- 在月内日期前添加一个仅供绘图的 `(起点, 0)`，横轴为 `起点、1、2……`。1 号只有一个真实采样点时，从起点连线到该点；真实采样点有清晰标记。
- 起点不称作“0号”，也不伪装成上月最后一天的数据。它不是观测值；悬浮时只显示“绘图起点”，不展示账号请求明细。
- 起点不写入存储、不参与总数、占比、排序和平均值；现有趋势按成功请求绘制的口径保持不变。
- 月内已发生但没有成功请求的日期补零；未来日期不补零。整月无数据保留空状态。
- Y 轴从零起，按标签长度预留空间，避免截图中的 `1…` 截断。切月及本地日期边界使用系统时间，覆盖月初／年初场景。

现状证据：概览 `buildMonthDays` 从 1 号生成到当前日期；`TrendChart` 的 markers 默认大小为 0，因此单个数据点不能形成折线。

## 3. OpenAI 额度展示

### 表格摘要

保留现有表格的单行布局与 `py-2` 内边距，所有账号行保持相同行高。OpenAI 额度沿用现有纯百分比外观，例如 `18%`；不显示“5小时”等周期文字，也没有箭头、分隔线、进度条或第二行文字。周期仅在悬浮详情中显示。浮层采用覆盖定位，不撑高行。

选择规则：仅在主额度窗口中按有效 `window_minutes` 从小到大选择第一档，不按已用百分比的大小选择，也不从附加模型额度中挑选。`5小时 + 7天` 只显示 5小时对应用量；`7天 + 30天` 只显示 7天对应用量。只返回一个主窗口时显示该窗口，主窗口缺失时显示 `—`；其他已返回额度仍可在悬浮详情查看。不为缺失值造 0%。

窗口长度按实际数据格式化，不能硬编码所有账号都是 5 小时／7 天。百分比含义始终为“已用”，在浮层表头和可访问标签中明确，与 `used_percent` 一致。

默认文字颜色，接近耗尽（建议 ≥80%）仅百分比变橙色，达到上限（≥100%）变红色。此阈值只是视觉提醒，不决定服务端是否允许重置。

### 详情浮层

沿用现有鼠标移入显示、移出关闭的 Tooltip 交互，内容改为紧凑明细，跟随主题采用白／深色底、细边框、轻阴影。建议宽约 440px，5 个额度窗口约 210–240px 高。去掉点击固定展开和关闭按钮；键盘聚焦也可查看，Escape 可关闭，靠近边缘自动换向。

- 删除顶部重复账号名称，浮层直接从四列表头开始，不保留空白标题区，也不增加“用量详情”等替代标题。
- 四列：`额度池 | 周期 | 已用 | 重置时间`，一个窗口只占一行。取消全部进度条。
- 同一额度池的名称跨行合并，仅出现一次；组间使用轻分隔线，不另设大标题。保留服务返回的完整额度池名，长名称允许换行。
- 主额度优先，其余额度池按稳定顺序展示；0% 仍可见，颜色弱化。时间缺失显示 `—`，可访问描述说明未提供。
- 时间列只写 `9/8 20:19` 这样的绝对时间，不逐行重复“自动重置”。以用户本地时区显示；过去的时间显示 `待同步`，不在客户端直接清零。
- 删除底部“同步状态：已更新”和第二个重置入口。只有同步失败、数据过旧等异常才补充提示；正常状态不占空间。
- 鼠标从触发内容移入浮层时维持显示，离开后关闭；不需要点击，也不固定展开。多额度时限制浮层高度并允许滚动。

## 4. OpenAI 重置卡

表头改为 `签到 / 重置`。newapi、sub2api 保留既有签到逻辑。整列统一复用 Badge 外观，建议高度 20px、最小宽度 58px、同一字号／圆角／内边距，居中对齐。可操作状态内部使用 button 语义，但不变成大号描边按钮；不可操作状态也不能退化成裸文字。

| 服务状态 | 单元格与操作 |
| --- | --- |
| 可用张数 > 0 | 淡蓝标签 `重置`，点击打开就地确认，不显示张数 |
| 确认返回 0 张 | 同样显示 `重置`，灰色禁用，不可执行兑换 |
| 尚未返回／获取失败 | 显示 `重置`，灰色禁用；通过刷新重新查询，不能当作 0 张 |
| 需要重新登录 | 显示登录状态并沿用重新登录入口 |
| 正在兑换 | 保持 `重置`，锁定本账号操作防止重复点击，使用可访问状态说明正在处理 |
| 其他账号已签到 | 同尺寸淡绿标签 `已签到` |
| 其他账号不支持签到 | 同尺寸灰色标签 `无签到` |

重置使用按钮附近的小型确认浮层，约 292px 宽。不显示标题，也不保留标题占位或额外顶部间距，直接显示正文 `消耗重置卡，重置 Gmail 用量，当前可用 2 张。`，账号名称和可用张数取所选账号的实际数据，只在正文出现。底部仅 `取消` 和 `确认重置`。通过不可见的可访问名称标识确认浮层。不复制主额度、周期或已用比例。卡片有效期／范围只在服务返回额外限制且影响决策时补充。

只确认使用一张卡重置服务端判定符合条件的额度，不承诺所有额度池清零。数量来自当前所选账号的已确认数据；不预测兑换后的剩余数量，操作完成后重新查询。点击外部或 Escape 取消，键盘打开时优先聚焦取消，关闭后回到原触发标签。兑换仍需用户明确点击 `确认重置`。

用户点击确认才调用兑换；不与每日签到、定时任务或余额刷新联动。默认由服务端选择下一张可用卡，不自行猜测选卡顺序。

同一次兑换尝试生成一个幂等键，网络重试必须复用。结果分别处理：

- `reset`：兑换成功，重新读取额度与卡片数量。
- `alreadyRedeemed`：同次兑换此前成功，同样刷新，不再次消耗。
- `nothingToReset`：提示暂无符合条件的用量可重置，不显示成功清零。
- `noCredit`：提示没有可用重置卡，刷新数量。
- 网络超时：提示结果待确认，允许用相同幂等键重试，不能发起新的兑换替代查询。
- 兑换成功但后续刷新失败：明确显示“重置成功，用量同步失败”，保留旧数据并提示重新同步。

本次开发验证使用模拟上游，未调用真实账号的兑换接口。

## 5. 已核实能力与接入

OpenAI 官方文档已核实（检索／读取时间：2026-09-08，系统时间）：

来源：[Codex App Server — Auth endpoints](https://learn.chatgpt.com/docs/app-server)。

- `account/rateLimits/read` 可返回 `rateLimitResetCredits.availableCount` 及 `credits` 明细；字段可能为 null，明细可能只有部分，张数以 `availableCount` 为准。
- `account/rateLimitResetCredit/consume` 支持 `idempotencyKey` 和可选 `creditId`，并返回上述四类业务结果；使用后需重新读取额度。

进一步读取 OpenAI 官方源码的 [rate_limit_resets.rs](https://github.com/openai/codex/blob/main/codex-rs/backend-client/src/client/rate_limit_resets.rs) 与其测试后，已核实当前 HTTP 合同：

- `GET https://chatgpt.com/backend-api/wham/usage` 返回 `rate_limit_reset_credits.available_count`。
- `POST https://chatgpt.com/backend-api/wham/rate-limit-reset-credits/consume`，请求体 `{ "redeem_request_id": "UUID" }`。
- HTTP 响应 `code` 为 `reset`、`already_redeemed`、`nothing_to_reset` 或 `no_credit`。

CliSwitch 已沿用原有账号鉴权实现该合同，未增加 CLI / app-server 运行依赖。前端接口为 `POST /api/openai/accounts/{id}/quota/reset`，使用 `idempotency_key`；返回 `outcome`、账号与 `quota_refresh_error`。新增可空缓存字段 `quota_reset_available_count`，旧库启动时补列；响应头额度更新保留卡片计数。

前端不接收 access token。业务接口绑定所选账号 ID。兑换确认后先失效旧卡数，再在限定时间内刷新；即使刷新失败，也返回已知兑换结果，避免诱发新兑换。前端在本地保存未确认幂等键，支持跨页面重试，刷新失败时锁定下一次消费。
